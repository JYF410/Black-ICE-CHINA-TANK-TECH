## 一、故障 A：满地图的科研按钮

### 现象

- 载入游戏后，地图上散布着大量"数字 + 左箭头"小方块；
- 科技树按钮点开也没有内容。

### 日志特征（决定性证据）

```
interface/countrytechtreeview.gui (line 31): Could not find "trm_armour_chi_folder" in window countrytechtreeview
interface/countrytechtreeview.gui (line 22662): Could not find "trm_armour_chi_folder_tab" in window folder_tabs
Parent window for BI_tech_queue_trm_armour_chi_folder is not found.
```

含义：

1. 游戏加载的 `countrytechtreeview.gui` 里**没有**我们的民国文件夹 → 说明这份文件来自别的 mod；
2. `BI_tech_queue_trm_armour_chi_folder`（我们的 scripted GUI 点击层）还在，但它要挂的父窗口不存在；
3. 父窗口缺失时，脚本 GUI 的元素不会消失，而是按 `global.tech_x/tech_y` 的**屏幕坐标**直接绘制 → 撒在地图上。

### 根因

`.gui` 是**整文件替换**：播放集里**最后加载**的、带同名文件的 mod 生效。

当时的顺序：

```
23  3463196432  黑冰：中国国民革命军坦克科技
...
34  3808452657  BlackICE Aircraft Designer   ← 它也有 interface/countrytechtreeview.gui
```

飞机设计器在后面，于是它的文件覆盖了我们的。

### 修法

启动器 → 播放集 → 把 **「黑冰：中国国民革命军坦克科技」拖到最底部**（在所有带 `countrytechtreeview.gui` 的 mod 之后），保存、重启。

### 注意

启动器在某些操作后会**按名字重新排序**（本 mod 名字以"黑冰："开头，很容易被排到中间）。每次动过播放集，回头确认它仍在最后。

## 二、故障 B：科技树连接线消失

### 现象

- 文件夹能打开，科技图标在，但**底盘科技之间没有灰色连线**；
- 图标位置和连线都对不上。

### 定位过程

1. 打开**德国坦克科技树**对照 → GER 连线正常；
   → 排除引擎/GUI 全局问题，范围缩小到我们自己的文件夹数据。
2. 查 `error.log`：只有 2 条无关的 `Found no grid box`（苏联科技），没有我们的报错；
3. 对比文件夹结构：民国文件夹 36 个科技，`gridboxtype` 只有 22 个。

### 根因

`gridboxtype` 是科技在科技树里的"槽位"。

- **没有槽位**的科技，引擎仍会用 `folder.position` 把图标画出来（所以图标在）；
- 但**槽位是连线（path/leads_to_tech）的锚点**，没有槽位就连不出线。

缺失的 14 个正好是整条底盘链：

```
tech_trm_tankette_tank_chassis_chi_cv33 / cv35 / ue
tech_trm_tankette_tank_chassis_chi_cardenloyd_mkVI
tech_trm_light_tank_chassis_chi_zb_1 / panzer1a / panzer2a / panzer2c
tech_trm_light_tank_chassis_chi_vickers_mke / t26b_1 / t26b_2 / m3a3
tech_trm_medium_tank_chassis_chi_panzer3a / m4a4
```

### 修法

为每个缺失的科技补一个槽位（与已有 22 个写法一致）：

```
gridboxtype = {
    name = "tech_trm_tankette_tank_chassis_chi_cv33_tree"
    position = { x = 190 y = 172 }
    slotsize = { width = 70 height = 70 }
    format = "UP"
}
```

`position` 用文件夹的网格原点 (190,172)，槽位尺寸 70×70，与年份行间距一致。

结果：槽位 1362 → 1376，连线恢复。

## 三、故障 C：`is_tech_ai_valid` 非法效果

技术文件里写成：

```
on_research_complete = {
    set_temp_variable = { tech = token:tech_trm_chi_armour }
    is_tech_ai_valid = yes        ← 触发器名，不是效果
}
```

日志：

```
Invalid effect 'is_tech_ai_valid' in common/technologies/TRM_armour_CHI.txt line : 112
Error: "Unknown effect-type: is_tech_ai_valid, near line: 112"
```

黑冰本体一次都没用过这个词。它会让 `on_research_complete` 后续效果中断，并且每次开局刷 40 条错误。

已把 `TRM_armour_CHI.txt`（29 处）与 `armor_techs_CHI.txt`（11 处）里的 40 行全部注释掉。

## 四、经验：这几个"看起来像美术问题"的现象其实是数据问题

1. **科技树连线不是 GUI 画的**，是引擎按科技定义里的 `path = { leads_to_tech = X }` 画的；GUI 里只需要 `gridboxtype` 提供槽位。所以：
   - 连线没了 → 先查 `gridboxtype`，再查 `path`；
   - `path` 在技术定义里是**科技根层**（与 `folder` 平级），不是写在 `folder` 里面（原版 `armor.txt` 实证）。
2. **文本框的 `maxWidth` 不是定位参数**：`maxWidth = 10000` 只是最大宽度，不会把文字推向右边；它反而会让鼠标永远命中这个超宽文本框（`gui` 控制台会误报所属容器）。
3. **`drag_scroll` 会让坐标"白改"**：中键平移只移动内容、不动窗口边框，看起来就像"怎么改都不动"。判断方法：看最左列科技图标是否在预期位置（本 mod 约 x≈830，未平移时）。
4. **`.gui` 是整文件替换**：只要播放集里有 mod 排在后面且带同名文件，你的所有 GUI 修改都不存在。排查任何"GUI 改了没反应"，第一件事就是确认自己在最后。

## 五、通用排查顺序（下次按这个走）

1. **确认文件被加载**：改一个唯一值（如 `maxWidth` 改成特殊数字），用 `gui` 控制台或 `error.log` 里带行号的报错核对；
2. **确认加载顺序**：`error.log` 搜 `Could not find "<你的窗口名>"`，有就是被别人盖了；
3. **确认作用域**：`on_startup` 没有当前作用域，必须 `every_country = { limit = { tag = XXX } ... }` 内联，不能直接调 scripted_effect；
4. **确认 UI 层 vs 数据层**：图标没连线的先看 `gridboxtype`，再想 `path`；
5. 最后才是坐标微调（而且要先把 `drag_scroll` 平移量排除）。

## 六、日志速查表

| 日志 | 含义 | 处理 |
|---|---|---|
| `Could not find "<文件夹名>" in window countrytechtreeview` | 加载的 .gui 里没有你的文件夹 → 被后面 mod 覆盖 | 把本 mod 拖到最后 |
| `Parent window for BI_tech_queue_xxx is not found` | scripted GUI 找不到父窗口，控件会画到地图上 | 同上 |
| `Found no grid box for tech xxx` | 该科技缺 `gridboxtype` 槽位 | 补 `gridboxtype` |
| `Invalid effect 'is_tech_ai_valid'` | 把触发器当效果用 | 删掉该行 |
| `Token xxx is a dynamic token ... OOS` | 全局动态 token 警告，黑冰自己也一堆 | 可忽略 |
